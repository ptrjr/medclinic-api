## Reprodução no PowerShell

Use um projeto Compose exclusivo que não esteja em uso por outra execução. Confira os labels do container e a porta antes de conectar; este ambiente é descartável. Não use o Compose de desenvolvimento nem credenciais de produção. As credenciais abaixo são somente as fictícias do Compose de integração versionado.

```powershell
$env:INTEGRATION_DB_HOST = '127.0.0.1'
$env:INTEGRATION_DB_PORT = '55434'
$env:INTEGRATION_DB_USERNAME = 'integration'
$env:INTEGRATION_DB_PASSWORD = 'integration-only-password'
$env:INTEGRATION_DB_DATABASE = 'medclinic_integration_test'
$env:TZ = 'Pacific/Auckland'
$functionalProject = 'medclinic-functional-stage3-20261029'
$existingContainers = docker ps -a --filter "label=com.docker.compose.project=$functionalProject" --format '{{.Names}}'
if ($LASTEXITCODE -ne 0) { throw 'Falha ao inspecionar containers' }
$existingNetworks = docker network ls --filter "label=com.docker.compose.project=$functionalProject" --format '{{.Name}}'
if ($LASTEXITCODE -ne 0) { throw 'Falha ao inspecionar redes' }
if ($existingContainers -or $existingNetworks) { throw 'Projeto já existe: preservar e inspecionar os recursos antes de prosseguir' }
try {
  docker compose -p medclinic-functional-stage3-20261029 -f compose.integration.yaml up -d --wait
  if ($LASTEXITCODE -ne 0) { throw 'Falha ao preparar PostgreSQL descartável' }
  npm.cmd run build
  if ($LASTEXITCODE -ne 0) { throw 'Build falhou' }
  npm.cmd run test:integration
  if ($LASTEXITCODE -ne 0) { throw 'Integração falhou' }
  npm.cmd run test:functional
  if ($LASTEXITCODE -ne 0) { throw 'Validação funcional falhou' }
} finally {
  docker compose -p medclinic-functional-stage3-20261029 -f compose.integration.yaml down
}
```

O executor reescreve a matriz deste relatório com os resultados de cada execução. Revise os registros complementares abaixo ao repetir a validação. O servidor recebe porta livre automaticamente. Requisições e comandos de bootstrap têm timeouts; o encerramento libera o servidor, schema, advisory lock e pool em `finally`, também em falhas. A proteção de loopback, nome exato do banco e versão 16 é reutilizada de `tests/integration/config.ts`; a suíte transacional e seus guards não foram relaxados.

O schema `public` também precisa estar vazio antes da primeira limpeza. O executor só passa a ter autorização para limpar depois dessa verificação; um schema pré-existente é preservado, inclusive no `finally`. O encerramento do servidor tem espera limitada e fallback de interrupção, e a liberação de lock, conexão e pool é tentada separadamente mesmo se uma dessas etapas falhar.
